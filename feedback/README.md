# Review feedback

Written reviews of the documents in this repository, kept as a record.

A review here is one member's assessment, **not alliance consensus**. Reviews are published so the reasoning behind a change is visible alongside the change itself — and so feedback that was *not* adopted stays on the record rather than disappearing.

## How to submit a review

Open a pull request adding one file, `feedback/YYYY-MM-short-description.md`, containing:

- **Who you are, and any interest that bears on the review.** What you build, what you sell, and what you would gain if a recommendation were adopted. State it even if you think it is obvious.
- **Which version you read.** Name the commit or release, so a later reader knows what you were looking at.
- **Ranked recommendations**, each specific enough to be acted on or rejected on its own.

Reviews are welcome whether or not their recommendations are adopted, and whether or not you are a repository collaborator.
